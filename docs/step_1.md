# Шаг 1. Тестовый образец MobileGateway

## Цель

Подготовить тестовый APK, который можно скопировать на Android-телефон, установить, открыть и проверить минимальный интерфейс с двумя кнопками: **«Старт»** и **«Стоп»**.

На этом этапе не подключаются сервер, камера, авторизация и настройки подключения. Задача шага — подтвердить, что каркас Flet собирается, устанавливается и работает на устройстве.

## Поведение тестового образца

- Экран содержит статус и две крупные кнопки.
- **Старт**: переводит приложение в состояние «Работает», включает видимый индикатор (текст, иконка, счётчик секунд или простой лог). Кнопка «Старт» становится неактивной.
- **Стоп**: переводит приложение в состояние «Остановлено», останавливает индикатор. Кнопка «Стоп» становится неактивной.
- Повторные нажатия не должны ломать состояние.
- Никаких сетевых запросов и секретов на этом этапе нет.

## Шаги выполнения

### 1. Подготовить окружение

- **Windows**: включить «Режим разработчика» — это требуется для `flet build apk`.
- **Зависимости проекта**: выполнить в корне проекта `poetry install`.
- **Android-телефон**: разрешить установку APK из выбранного источника (файловый менеджер, ADB, облако и т.д.).
- **Сборка APK**: проверить, что `poetry run flet build apk` может выполниться. При первом запуске Flet может докачивать нужные компоненты; если сборка запросит Flutter/Android SDK/JDK, доустановить их по сообщению инструмента.

### 2. Привести текущий каркас в рабочее состояние

- Проверить импорт в `main.py`: сейчас используется `from ui.main_window import MainWindow`, тогда как файл находится в `src/ui/main_window.py`. Привести импорт к рабочему виду, например `from src.ui.main_window import MainWindow`, и проверить запуск.
- Убедиться, что `main.py` остаётся единой точкой входа и `ft.run(main)` корректно работает с текущей версией Flet 1.x.
- Убедиться, что минимальный UI не зависит от реального `API_URL`, `STREAM_URL` или других серверных настроек.

### 3. Реализовать минимальный UI

- В `src/ui/main_window.py` или выделенном экране собрать простой макет:
  - `Text` со статусом: `Остановлено` / `Работает`.
  - Кнопка **«Старт»** (`ElevatedButton`/`FilledButton`).
  - Кнопка **«Стоп»** (`ElevatedButton`/`OutlinedButton`).
- Сделать кнопки удобными для тапа на телефоне: достаточные отступы, размер и ширина.
- Добавить обработчики:
  - `on_start` — переключает состояние, обновляет статус/индикатор, обновляет страницу или контрол.
  - `on_stop` — останавливает состояние и обновляет UI.
- Исключить повторный запуск уже активного состояния: блокировать активную кнопку или игнорировать повторное нажатие.

### 4. Проверить локально на ПК

Запуск:

```bash
poetry run flet run main.py
```

Проверить:

- окно открывается без ошибок импорта;
- кнопка «Старт» меняет статус;
- кнопка «Стоп» возвращает статус;
- повторные нажатия не ломают состояние;
- закрытие приложения не оставляет фоновой задачи, если используется таймер или цикл.

### 5. Проверить на телефоне в режиме разработки

Условия: ПК и телефон в одной Wi-Fi сети, на телефоне установлено приложение Flet.

Запуск:

```bash
poetry run flet run --android main.py
```

Проверить:

- экран корректно отображается на телефоне;
- кнопки нажимаются и меняют состояние;
- приложение не падает при сворачивании и возврате.

Этот шаг полезен до сборки APK: он быстрее позволяет найти проблемы UI.

### 6. Собрать APK

Команда:

```bash
poetry run flet build apk
```

Если Flet запросит недостающие компоненты, установить их и повторить сборку. Готовый артефакт проверить в `build/apk/`.

### 7. Установить и протестировать APK на телефоне

- Скопировать APK на телефон и установить.
- Выполнить smoke-тест:
  - приложение запускается;
  - видны кнопки «Старт» и «Стоп»;
  - «Старт» меняет состояние;
  - «Стоп» меняет состояние;
  - поворот экрана, сворачивание и возврат не приводят к крэшу.

### 8. Зафиксировать результат

- Записать результат проверки: версия Android, способ установки, размер APK, проблемы сборки или запуска.
- После успешного smoke-теста перейти к следующему инкременту: экран настроек (`API_URL`, токен), проверка соединения, затем замена тестового Start/Stop на реальные команды серверу.

## Критерии готовности

- APK собирается локально.
- APK устанавливается на телефон.
- Приложение открывается.
- Две кнопки видны и работают предсказуемо.
- Для работы тестового образца не требуется сервер.
