# Шаг 2. Настройки подключения и проверка связи с сервером

## Цель

Расширить тестовый образец до минимально полезного мобильного клиента: пользователь может открыть APK, ввести параметры подключения, сохранить их на устройстве, проверить связь с сервером и увидеть понятный результат.

На этом шаге **не** реализуются камера, видеопоток, авторизация через логин/пароль и полноценный протокол команд. Start/Stop пока остаются тестовыми или получают только простой заглушечный вызов, если API ещё не готов.

## Результат шага

- В приложении есть экран/раздел **«Настройки»**.
- Пользователь может указать:
  - `API_URL` — базовый адрес сервера, например `http://192.168.1.100:8000`;
  - `API_TOKEN` — токен/ключ (необязательно, если сервер пока без авторизации);
  - `HEALTH_ENDPOINT` — путь проверки связи, по умолчанию `/health` или другой согласованный путь.
- Настройки сохраняются локально на устройстве и восстанавливаются после перезапуска приложения.
- Кнопка **«Проверить соединение»** выполняет HTTP-запрос и показывает состояние: `Успех`, `Ошибка`, `Таймаут`, `Нет сети/неверный адрес`.
- Тестовый Start/Stop не ломается.

## Ограничения и допущения

- Формат API пока неизвестен/может измениться. Поэтому проверку связи нужно сделать конфигурируемой: адрес и endpoint задаёт пользователь.
- На Android нельзя рассчитывать на запись в `.env` внутри APK. Настройки сохранять через локальное хранилище Flet (`page.client_storage`).
- Не логировать токен и не показывать его целиком в ошибках.
- Сетевые вызовы выполнять асинхронно, не блокируя UI.

## Шаги выполнения

### 1. Уточнить минимальный контракт сервера

Перед кодированием зафиксировать (даже временно) 1 простой endpoint для проверки:

- **Вариант A (предпочтительно):** `GET {API_URL}{HEALTH_ENDPOINT}` возвращает `200 OK`.
- **Вариант B:** любой существующий безопасный GET-endpoint, который не меняет состояние сервера.

Если сервера ещё нет, сделать локальную заглушку на ПК (FastAPI/Flask) или проверять на публичном тестовом URL — только для отладки UI. В финальном тесте использовать реальный адрес сервера.

### 2. Подготовить модель настроек

Создать/уточнить структуру настроек в `src/core/config.py` или отдельном модуле, например `src/core/settings_store.py`.

Настройки должны включать:

- `api_url: str`
- `api_token: str`
- `health_endpoint: str` (по умолчанию `/health`)
- `timeout: float` (по умолчанию 10.0)

Правила:

- нормализовать `api_url`: убрать пробелы, убрать завершающий `/` при сборке URL;
- нормализовать `health_endpoint`: гарантировать ведущий `/`;
- не хранить секреты в коде; значения по умолчанию — безопасные.

### 3. Добавить локальное хранение настроек

Использовать `page.client_storage` (Flet) для сохранения/загрузки.

Предлагаемые ключи:

- `mg.api_url`
- `mg.api_token`
- `mg.health_endpoint`
- `mg.timeout`

Задачи:

- при старте приложения загрузить сохранённые значения;
- если значений нет — использовать дефолты из `Settings`;
- при нажатии «Сохранить» записать значения и показать подтверждение.

Важно: клиентское хранилище подходит для MVP. Для чувствительных данных позже рассмотреть более защищённое хранилище платформы.

### 4. Сделать экран настроек

Добавить UI-раздел «Настройки». Варианты навигации:

- простая `NavigationBar` с вкладками «Главная» / «Настройки»;
- или кнопка-иконка настроек в `AppBar`, открывающая отдельный экран.

Поля UI:

- `TextField` «Адрес сервера» (`API_URL`)
- `TextField` «Токен» (`password=True`, можно добавить кнопку показать/скрыть)
- `TextField` «Endpoint проверки» (`/health`)
- `TextField` или `Slider` «Таймаут, сек»
- кнопка «Сохранить»
- кнопка «Проверить соединение»

UI-состояния:

- загрузка: кнопка проверки disabled, показывается `ProgressRing`;
- успех: зелёный текст/иконка, код ответа, короткое сообщение;
- ошибка: красный текст/иконка, понятная причина без утечки токена.

### 5. Реализовать сервис проверки соединения

Создать сервис, например `src/core/api_client.py` или `src/services/health_service.py`, на базе `httpx.AsyncClient`.

Примерная логика:

```text
GET {api_url}{health_endpoint}
Headers:
  Authorization: Bearer <token>   # только если токен задан
Timeout: timeout
```

Обрабатывать случаи:

- успешный ответ `2xx`;
- HTTP ошибка `4xx/5xx` — показать статус-код и короткий текст;
- таймаут;
- ошибка DNS/соединения/неверный URL;
- неожиданное исключение — общий безопасный текст.

Возвращать структурированный результат, например:

```text
ok: bool
status_code: int | None
message: str
details: str | None
```

Не прокидывать сырой traceback в UI.

### 6. Подключить UI к сервису

- При нажатии «Проверить соединение» брать актуальные значения из полей (или сохранённые настройки).
- Валидировать URL до запроса: непустой, начинается с `http://` или `https://`.
- Выполнять запрос асинхронно.
- Показывать результат в карточке/баннере под кнопками.

Рекомендуемый текст результата:

- `Соединение установлено (200)`
- `Сервер ответил ошибкой (401)`
- `Таймаут после 10 сек`
- `Не удалось подключиться: проверьте адрес и сеть`

### 7. Сохранить совместимость с шагом 1

- Вкладка/экран «Главная» должен сохранить тестовые кнопки **Старт/Стоп**.
- Проверка соединения не должна ломать таймер.
- Ошибки сети не должны вызывать крэш приложения.

### 8. Локальная проверка на ПК

1. Запустить приложение:

   ```bash
   poetry run flet run main.py
   ```

2. Проверить сценарии:
   - пустой/неверный URL — валидация;
   - корректный URL недоступного сервера — понятная ошибка;
   - корректный endpoint доступного сервера — успех;
   - сохранение настроек после перезапуска приложения;
   - токен не отображается в логах/сообщениях об ошибке.

3. При необходимости поднять локальную заглушку:

   ```python
   # пример для ручной проверки, не обязательно коммитить
   from fastapi import FastAPI
   app = FastAPI()

   @app.get("/health")
   def health():
       return {"status": "ok"}
   ```

### 9. Проверка на Android

1. Быстрый прогон:

   ```bash
   poetry run flet run --android main.py
   ```

2. Проверить:
   - ввод настроек с экранной клавиатуры;
   - сохранение после закрытия/открытия;
   - проверка соединения по Wi-Fi;
   - поведение при неверном адресе/отсутствии сети.

3. Сборка APK:

   ```bash
   poetry run flet build apk --arch arm64-v8a
   ```

4. Установить APK на телефон и повторить smoke-тест.

### 10. Зафиксировать результат

В карточке темы и/или комментарии к шагу записать:

- какой endpoint использовался для проверки;
- нужен ли токен;
- как сохраняются настройки;
- какие ошибки сети проверены;
- что переносится в шаг 3.

## Критерии готовности

- APK открывается на телефоне.
- Экран настроек позволяет ввести `API_URL`, токен, endpoint проверки.
- Настройки сохраняются между перезапусками.
- Кнопка «Проверить соединение» даёт понятный результат для успеха и типовых ошибок.
- Тестовые кнопки Start/Stop продолжают работать.
- Никакие секреты (токен) не пишутся в UI-ошибки и логи.

## Следующий шаг после шага 2
