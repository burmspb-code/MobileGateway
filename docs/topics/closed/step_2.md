## Цель
Реализовать по `docs/step_2.md` экран настроек подключения, локальное сохранение параметров и проверку связи с сервером.

## Решено
- Шаг 2 выделен в отдельную тему; темы «Старт» и «Разработка GUI» закрыты 2026-11-25.
- Тестовый таймер/Start-Stop убран: он был нужен только для проверки UI; Главная — рабочая заглушка под будущие действия сервера.
- Настройки — служебный экран через `⚙` в AppBar; архитектура UI разделена на `AppShell` + отдельные view.
- Настройки хранятся через `SettingsStore`: `page.client_storage`, при недоступности — fallback в `connection_settings.json` (в `.gitignore`). Токен не логируется и не показывается в ошибках UI.
- Проверка связи конфигурируемая: `GET {API_URL}{HEALTH_ENDPOINT}` через `httpx`. На Главной только два состояния индикатора: зелёный (200/подключено) и красный (нет подключения/ошибка); авто-проверка выполняется при старте, возврате на Главную и после сохранения настроек.
- При выходе из Настроек с несохранёнными изменениями показывается диалог: сохранить / не сохранять / отмена.

## Сделано
- Собран каркас UI: `AppShell`, `HomeView`, `SettingsView`; таймер/Start-Stop удалены.
- Добавлена модель `ConnectionSettings` с нормализацией/валидацией (`api_url`, `api_token`, `health_endpoint`, `timeout`).
- Добавлен `SettingsStore` (сохранение/загрузка настроек, fallback JSON).
- Добавлен `ApiClient` для async-проверки `GET {API_URL}{HEALTH_ENDPOINT}` через `httpx`; безопасные сообщения об ошибках.
- Реализован индикатор подключения (зелёный/красный), авто-проверка при старте/возврате/сохранении, диалог несохранённых изменений.
- Ручная проверка на ПК: ввод/валидация, сохранение между перезапусками, реальный endpoint `https://194.58.223.7:8443/health` — `200`. Пользователь подтвердил контрольный тест и закрыл тему 2026-11-27.
