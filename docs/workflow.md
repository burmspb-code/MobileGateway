# Сценарии работы с темами

Универсальный файл. Не привязан к конкретному проекту.

## Старт

1. Проверить `git status --short`. Если есть незакоммиченные изменения, определить тему по пересечению файлов с её разделом «Файлы» и выполнить для неё «Финиш»: обновить карточку, связи, коммит. Тему не закрывать. Если тема не определяется — показать список изменений и уточнить, к какой теме их отнести. Секреты и `.env` в коммит не брать.
2. Прочитать `docs/INDEX.md` (правила проекта) и `docs/topics/INDEX.md` (реестр тем).
3. Если тем нет — сказать: «Начинаем новую тему. Дай название». После названия создать карточку по `docs/topics/_template.md` и добавить строку в реестр.
4. Если темы есть — показать список через встроенный инструмент выбора:
   - активные и ожидающие темы;
   - вариант «Архив» (показать закрытые);
   - вариант «Новая тема»;
   - в описании каждой — статус и первый шаг.
5. После выбора прочитать **только** выбранный файл темы и выдать брифинг на 3–5 строк: цель, статус, блокировка, следующий шаг. Затем ждать указаний.
6. Если «Начинаем работу» пришла в середине активной темы — выполнить «Смену темы»: зафиксировать текущую тему коммитом и показать список, без вопроса.

## Финиш

1. Обновить карточку текущей темы: цель, решено, сделано, блокировка, следующий шаг, файлы.
2. Всегда проверить `git diff --name-only` и добавить связи со всеми темами, в чьём разделе «Файлы» есть эти файлы. Не спрашивать.
3. Обновить `docs/topics/INDEX.md`, если изменились статус или следующий шаг.
4. Сделать коммит по правилу из раздела «Коммит».
5. Коротко сообщить: сделано / осталось / ждём / первый шаг. Если в дереве остались изменения, не относящиеся к сессии, не трогать их и отдельно сообщить.

## Закрытие темы

1. Выполнить шаги «Финиш».
2. Поставить теме `status: closed`, записать итог в карточку и перенести файл в `docs/topics/closed/`.
3. Убрать тему из основного реестра, обновить `docs/topics/INDEX.md`.
4. Сделать коммит.
5. Спросить через инструмент выбора: «Начинаем новую тему» или «Выбрать из существующих».

## Архив

1. Прочитать `docs/topics/closed/INDEX.md` (если есть) или перечислить файлы в `docs/topics/closed/`.
2. Показать список закрытых тем через инструмент выбора. Добавить вариант «Назад».
3. После выбора спросить: «Посмотреть» (не менять статус) или «Возобновить».
4. При «Возобновить» — вернуть файл из `closed/`, поставить `status: active`, обновить реестр, выдать брифинг. Коммит — по общему правилу в конце работы.

## Список тем

Показать тот же список, что в шаге 4 «Старта», без вопроса «продолжить или выбрать». Нужно, чтобы быстро сориентироваться, не запуская полный старт.

## Смена темы

1. Выполнить шаги «Финиш» для текущей темы: обновить карточку, добавить связи, сделать коммит. Тему не закрывать.
2. Показать список тем через инструмент выбора, как в шаге 4 «Старта».
3. Записать выбранную тему в `docs/handoff.md` и продолжить в текущей сессии. В новой сессии тема подхватится автоматически из handoff — повторять «Начинаем работу» не нужно. Для совсем чистого контекста можно открыть новую сессию, но это не обязательно.

## Связи

- Источник истины — та тема, в которой реально ведётся работа.
- В ней добавляется раздел «Затронутые темы» с одной строкой на каждую смежную тему.
- В смежной теме добавляется одна строка в раздел «Связи» с датой и указанием, что проверить.
- Статус смежной темы не меняется. Полное обновление — только после явного переключения на неё.

## Коммит

- Коммитить код и документацию вместе, сообщение `[тема] кратко`.
- Никогда не коммитить `.env`, ключи и секреты.
- Если менялся код — запустить тесты из `docs/INDEX.md`; при падении не коммитить и сообщить причину.
- Если изменений нет — сказать «нечего коммитить», пустой коммит не делать.
- Изменения, не относящиеся к текущей сессии, оставить нетронутыми и сообщить о них отдельно.
